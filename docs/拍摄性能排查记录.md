# 拍摄性能排查记录

日期：2026-10-16。

## 测量条件与结果

- 真机：vivo V2001A，Android 13；Profile 构建。
- 后置镜头、1×、JPEG、4:3、自动保存开启；室内同一墙面。
- 两次分别在安装并打开相机后测量一张；最终成片确认仍为 **3000×4000**。
- 计时范围：发起拍摄到自动保存完成，不含定时倒计时；不是严格的多次平均或相机预览响应时间测量。

| 步骤 | 优化前 | 最终小图块方案 |
| --- | ---: | ---: |
| 相机拍摄 | 767 ms | 806 ms |
| 恢复文件与初始记录 | 11 ms | 8 ms |
| 读图、绘制、编码及照片写入 | 1213 ms | 631 ms |
| 最终记录与清理 | 4 ms | 10 ms |
| 系统相册保存 | 111 ms | 119 ms |
| 总计 | **2107 ms** | **1574 ms** |

本轮样本总耗时下降约 25%，图像处理部分下降约 48%。用户此前反馈约 4 秒，本轮没有在相同配置下复现到该值，不能将样本改进描述成“稳定从 4 秒降到 1.57 秒”。低光、对焦、首次资源加载、手机负载、PNG 或其他水印模板仍可能影响耗时。

## 最终实现

1. Flutter 继续使用同一个 `PhotoWatermarkPainter`，收集文字、Logo、背景栏的实际绘制边界。
2. 扩展边界保留阴影，合并重叠区域，避免透明像素重复叠加；仅把这些区域渲染成原分辨率 PNG 小图块，不压缩水印几何尺寸。
3. Android 直接从相机原文件解码，依据 EXIF 方向及共享裁切范围合成水印，输出 JPEG；无需整张照片经过 Flutter GPU 解码、回读及大块像素传输。
4. 无需旋转和裁切时复用可变输入位图，减少整幅照片复制。JPEG 质量仍为 92，不降低分辨率。
5. 输出先写入应用照片目录的临时文件，成功后改名；失败时保留已有的应用内恢复记录，不直接把无水印原图存入相册。

曾实测全幅透明 PNG 图层方案：图层生成约 1288 ms，总耗时约 3184 ms，因此最终采用小图块，未保留全幅透明图层路径。

PNG 和其他平台保留原有跨平台处理路径，本轮速度结论仅适用于已测量的 Android JPEG 配置。

## 验证

- 静态分析通过，40 项自动测试通过。
- 模拟器原生合成检查通过 33 组：8 种 EXIF 方向 × 3 种比例，并额外覆盖四套水印模板；核对输出尺寸、方向和颜色。
- 保留双指缩放、照片翻页、3000×4000 水印相对尺寸、手动保存及相册删除的回归测试。
- 最终 Profile 包已覆盖安装真机，安装返回 `Success`。
- 测试照片与原始计时文件只位于被 Git 忽略的 `build/`，不加入文档截图或仓库。

## 诊断记录

Debug/Profile 每次只覆盖一份 `last_capture_performance.json`，记录格式、比例、自动保存开关与各步骤耗时，不记录照片内容、文件路径或位置数据。Release 不写该记录。

```powershell
adb -s <设备ID> shell cat /sdcard/Android/data/com.example.altivex/files/last_capture_performance.json
```
